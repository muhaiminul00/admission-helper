Replaces every plain, single-color progress_bar.html usage that represents real per-topic study data (Class/Notes/Revision/Practice, each an independent 25% - see progress.services.progress_service, the single source of truth this component always renders from; no page computes any of these numbers itself). Context vars: progress (required) - a dict from progress_service (topic_count, total_units, completed_units, percentage, dimensions, segments). size ("sm"/"md", default "md") - block/bar height. show_legend (optional bool, default False) - a small color key below the meter (Class/Notes/Revision/Practice). show_percentage (optional bool, default True) - the "N/M units" caption beside the meter. tooltip (optional bool, default True) - per-segment title attrs. extra_classes (optional). `show_percentage`/`tooltip` use `default_if_none`, not `default` - the plain `default` filter substitutes on *any* falsy value, so an explicit `tooltip=False` would be silently replaced by the "True" default (the same filter-semantics trap this project has hit before, e.g. `add`'s fallback string-concat behavior) and could never actually be turned off. Rendering adapts to progress.total_units alone (Part 5) - never a caller choice - so "the meaning stays identical while the rendering adapts": <=32 units renders individual blocks (grouped by dimension, narrower once above 16 - Part 5's small/medium tiers); >32 units renders one continuous 4-segment bar instead of dozens of tiny blocks (Part 5's large tier). {% endcomment %}
