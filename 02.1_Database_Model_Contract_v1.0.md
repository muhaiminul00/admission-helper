**Project:** Admission Helper\

This document is the authoritative specification for implementing

# 1. General Rules

## 1.1 Purpose

This document specifies every database model used in Version 1 of the
Admission Helper application.

The coding agent must implement the models exactly as defined here.

No additional models, fields, relationships, or constraints may be
introduced unless the design documents are updated.

## 1.2 Global Conventions

### Primary Keys

``` python
id = models.BigAutoField(primary_key=True)
```

### Foreign Keys

Every foreign key must define:

-   `related_name`
-   `on_delete`

### Nullability

Unless explicitly stated:

-   `blank=False`
-   `null=False`

### Ordering

Every model must define `Meta.ordering`.

### String Representation

Every model must implement `__str__()`.

### Migrations

Only Django-generated migrations are permitted. Migration files must
never be edited manually.

# 2. Subject Model

## Purpose

Represents an admission subject. Static data. Not imported from CSV.

## Fields

  --------------------------------------------------------------------------------------------------
  Field              Type                                     Required                Notes
  ------------------ ---------------------------------------- ----------------------- --------------
  id                 BigAutoField                             Yes                     Primary key

  code               CharField(max_length=20, unique=True,    Yes                     Subject code
                     db_index=True)                                                   

  name               CharField(max_length=100)                Yes                     Display name

  display_order      PositiveSmallIntegerField(unique=True)   Yes                     UI ordering
  --------------------------------------------------------------------------------------------------

## Relationships

None.

## Ordering

``` python
ordering = ["display_order"]
```

## Constraints

-   `code` unique
-   `display_order` unique

## `__str__()`

``` python
return f"{self.code} - {self.name}"
```

# 3. Chapter Model

## Purpose

Represents a chapter belonging to a subject. Static data.

Subjects are subject-level (e.g. Physics, not "Physics 1st Paper"), so a
subject's syllabus spans two papers, each with its own Chapter 1,
Chapter 2, etc. The `paper` field disambiguates which paper a chapter
belongs to; `subject` + `paper` + `chapter_no` together identify a
chapter uniquely.

## Fields

  -----------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- ------------------------------
  id                                       BigAutoField

  subject                                  ForeignKey(Subject,
                                           on_delete=CASCADE,
                                           related_name="chapters")

  paper                                    PositiveSmallIntegerField,
                                           choices=Paper.choices

  chapter_no                               PositiveSmallIntegerField

  name                                     CharField(max_length=200)

  display_order                            PositiveSmallIntegerField
  -----------------------------------------------------------------------

## Paper Choices

``` python
class Paper(models.IntegerChoices):
    FIRST = 1, "1st Paper"
    SECOND = 2, "2nd Paper"
```

## Constraints

Unique constraint:

-   (`subject`, `paper`, `chapter_no`)

## Ordering

``` python
ordering = ["subject", "paper", "chapter_no"]
```

## Indexes

-   subject
-   chapter_no

## `__str__()`

``` python
return f"{self.subject.name} - {self.get_paper_display()} - Chapter {self.chapter_no} - {self.name}"
```

# 5. Lecture Model

## Purpose

Represents one coaching lecture. Most Lecture rows are imported from a
`routine.csv` CLASS row and have a real scheduled date/day/time/title.

A Lecture may also be created without a schedule ("undated") when a
lecture_code is referenced by `lecture_topics.csv` or `exams.csv` but
has no `routine.csv` CLASS row - self-study subjects (no live class at
all) or an intentionally-skipped lecture number. This represents real
fact ("this lecture code exists, with no scheduled session") rather
than fabricated schedule data - no date/day/time/title is invented for
these rows.

## Fields

  -----------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- ------------------------------
  id                                       BigAutoField

  routine                                  ForeignKey(Routine,
                                           on_delete=CASCADE,
                                           related_name="lectures")

  lecture_code                             CharField(max_length=30)

  subject                                  ForeignKey(Subject,
                                           on_delete=PROTECT,
                                           related_name="lectures")

  title                                    CharField(max_length=200,
                                           blank=True, default="")

  lecture_date                             DateField(null=True,
                                           blank=True, db_index=True)

  day                                      CharField(max_length=20,
                                           blank=True, default="")

  start_time                               TimeField(null=True,
                                           blank=True)

  end_time                                 TimeField(null=True,
                                           blank=True)

  notes                                    TextField(blank=True)
  -----------------------------------------------------------------------

## Constraints

Unique constraint:

-   (`routine`, `lecture_code`)

## Ordering

``` python
ordering = ["lecture_date", "start_time"]
```

## Indexes

-   lecture_date
-   lecture_code
-   subject

## `__str__()`

``` python
return self.lecture_code
```

# 6. LectureTopic Model

## Purpose

Represents the smallest study unit.

`chapter` is nullable: subjects with no chapter breakdown in
`chapters.csv` (English, Bangla in this dataset - determined
dynamically at import time, not hardcoded) have topics with no real
chapter reference to attach to. `None` accurately represents "this
subject has no chapters", rather than a chapter being fabricated.

## Fields

  -------------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- --------------------------------
  id                                       BigAutoField

  lecture                                  ForeignKey(Lecture,
                                           on_delete=CASCADE,
                                           related_name="topics")

  chapter                                  ForeignKey(Chapter,
                                           on_delete=PROTECT,
                                           related_name="lecture_topics",
                                           null=True, blank=True)

  topic                                    CharField(max_length=255)

  display_order                            PositiveSmallIntegerField
  -------------------------------------------------------------------------

## Constraints

Unique constraint:

-   (`lecture`, `chapter`, `topic`)

## Ordering

``` python
ordering = ["lecture", "display_order"]
```

## Indexes

-   lecture
-   chapter

## `__str__()`

``` python
return self.topic
```

# 7. Progress Model

## Purpose

Tracks one user's study completion for one LectureTopic.

Milestone 7 made Progress per-user: `lecture_topic` changed from
`OneToOneField` to `ForeignKey` (many users can each have their own
Progress row for the same topic), and a `user` field was added. The
`(user, lecture_topic)` UniqueConstraint below is what now enforces
"at most one Progress row per user per topic" - the job the field-level
OneToOne uniqueness used to do alone.

## Fields

  -----------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- ------------------------------
  id                                       BigAutoField

  user                                     ForeignKey(settings.AUTH_USER_MODEL,
                                           on_delete=CASCADE,
                                           related_name="progress_records")

  lecture_topic                            ForeignKey(LectureTopic,
                                           on_delete=CASCADE,
                                           related_name="progress_records")

  class_done                               BooleanField(default=False)

  notes_done                               BooleanField(default=False)

  revision_done                            BooleanField(default=False)

  practice_done                            BooleanField(default=False)

  updated_at                               DateTimeField(auto_now=True,
                                           db_index=True)
  -----------------------------------------------------------------------

## Constraints

Unique constraint:

-   (`user`, `lecture_topic`)

## Ordering

``` python
ordering = ["updated_at"]
```

## `__str__()`

``` python
return f"{self.user} - {self.lecture_topic.topic}"
```

# 8. RevisionSchedule Model

## Purpose

Represents one user's revision stage for one fully-completed Lecture
(Milestone 9). A lecture's three revision stages (First/Second/Final)
are created together, all at once, the moment the lecture becomes
fully completed (every one of its topics completed - see
`progress/services/revision.py: ensure_revision_schedule()`).
Deterministic only: due dates are computed from fixed interval
constants, never AI-generated or randomized.

Deliberately references `Lecture`, not `LectureTopic` or `Chapter` -
revision is scheduled per-lecture (its topics collectively define
"what to revise"), so no lecture/topic data is duplicated here.

## Fields

  -----------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- ------------------------------
  id                                       BigAutoField

  user                                     ForeignKey(settings.AUTH_USER_MODEL,
                                           on_delete=CASCADE,
                                           related_name="revision_schedules")

  lecture                                  ForeignKey(Lecture,
                                           on_delete=CASCADE,
                                           related_name="revision_schedules")

  revision_level                           PositiveSmallIntegerField,
                                           choices=Level.choices

  due_date                                 DateField(db_index=True)

  completed_at                             DateTimeField(null=True,
                                           blank=True)

  status                                   CharField(max_length=20,
                                           choices=Status.choices,
                                           default="pending",
                                           db_index=True)

  created_at                               DateTimeField(auto_now_add=True)

  updated_at                               DateTimeField(auto_now=True)
  -----------------------------------------------------------------------

## Revision Level Choices

``` python
class Level(models.IntegerChoices):
    FIRST = 1, "First Revision"
    SECOND = 2, "Second Revision"
    FINAL = 3, "Final Revision"
```

## Status Choices

``` python
class Status(models.TextChoices):
    PENDING = "pending", "Pending"
    COMPLETED = "completed", "Completed"
```

## Constraints

Unique constraint:

-   (`user`, `lecture`, `revision_level`) - prevents duplicate
    schedules for the same lecture/user/stage.

## Ordering

``` python
ordering = ["due_date", "revision_level"]
```

## `__str__()`

``` python
return f"{self.user} - {self.lecture.lecture_code} - {self.get_revision_level_display()}"
```

# 9. RevisionHistory Model

## Purpose

An immutable, append-only record of one completed revision (Milestone
9). Never deleted or edited - `RevisionSchedule.completed_at`/`status`
reflect only the current state, while this table is the durable audit
trail of every completion event.

## Fields

  -----------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- ------------------------------
  id                                       BigAutoField

  revision_schedule                        ForeignKey(RevisionSchedule,
                                           on_delete=CASCADE,
                                           related_name="history")

  completed_at                             DateTimeField

  notes                                    TextField(blank=True,
                                           default="")
  -----------------------------------------------------------------------

## Ordering

``` python
ordering = ["-completed_at"]
```

## `__str__()`

``` python
return f"{self.revision_schedule} completed {self.completed_at}"
```

# 10. Exam Model

## Purpose

Represents one coaching exam imported from `exams.csv`.

`exam_code` (e.g. `WE-01`, `MRT-01`) is the exam's natural, unique
identifier in the finalized dataset - it doubles as the import
lookup key, so re-running the importer never creates duplicate Exam
rows. `online_start`/`online_end` are the exam's online availability
window. The finalized `exams.csv` has no `notes` column; `notes`
remains available for manual/future use but is not populated by import.

## Fields

  -----------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- ------------------------------
  id                                       BigAutoField

  routine                                  ForeignKey(Routine,
                                           on_delete=CASCADE,
                                           related_name="exams")

  exam_code                                CharField(max_length=30,
                                           unique=True)

  exam_name                                CharField(max_length=200)

  exam_type                                CharField(max_length=20,
                                           choices=ExamTypeChoices)

  exam_date                                DateField(db_index=True)

  online_start                             DateField(null=True,
                                           blank=True)

  online_end                               DateField(null=True,
                                           blank=True)

  covered_lectures                         JSONField(default=list)

  notes                                    TextField(blank=True)
  -----------------------------------------------------------------------

## Constraints

-   `exam_code` unique

## Exam Type Choices

``` python
class ExamType(models.TextChoices):
    WEEKLY = "Weekly", "Weekly"
    MONTHLY = "Monthly", "Monthly"
    SPECIAL = "Special", "Special"
```

## Ordering

``` python
ordering = ["exam_date"]
```

## Indexes

-   exam_date
-   exam_type

## `__str__()`

``` python
return self.exam_name
```

# 11. DatasetVersion Model

## Purpose

Represents one imported CSV dataset snapshot (Milestone 10). Created
automatically by every successful `import_csv` run (never by
`--preview`/`--dry-run`, which write nothing). `source` holds the
directory the source CSVs for this version were archived to
(`routines/services/dataset/versioning.py: archive_source_csvs()`) -
this is what makes `rollback_dataset` able to restore a previous
version's actual data, since `statistics` is only a summary, not a row
snapshot.

## Fields

  -----------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- ------------------------------
  id                                       BigAutoField

  version_name                             CharField(max_length=100,
                                           unique=True)

  source                                   CharField(max_length=500)

  description                              TextField(blank=True,
                                           default="")

  imported_by                              ForeignKey(settings.AUTH_USER_MODEL,
                                           on_delete=SET_NULL, null=True,
                                           blank=True,
                                           related_name="dataset_versions")

  imported_at                              DateTimeField(auto_now_add=True)

  is_active                                BooleanField(default=False)

  checksum                                 CharField(max_length=64)

  statistics                               JSONField(default=dict)
  -----------------------------------------------------------------------

## Constraints

-   Partial unique constraint: `is_active` unique where
    `is_active=True` - guarantees at most one active dataset at the
    database level, not just in application logic.

## Ordering

``` python
ordering = ["-imported_at"]
```

## `__str__()`

``` python
return self.version_name
```

# 12. ImportLog Model

## Purpose

An audit record of one `import_csv` run - success, failure, preview,
dry run, or rollback (Milestone 10). Written regardless of outcome, so
"what happened last time an import was attempted" is always answerable
from the database, not just from console output that may already be
gone.

## Fields

  -----------------------------------------------------------------------
  Field                                    Type
  ---------------------------------------- ------------------------------
  id                                       BigAutoField

  dataset_version                          ForeignKey(DatasetVersion,
                                           on_delete=SET_NULL, null=True,
                                           blank=True,
                                           related_name="import_logs")

  importer_version                         CharField(max_length=20)

  user                                     ForeignKey(settings.AUTH_USER_MODEL,
                                           on_delete=SET_NULL, null=True,
                                           blank=True,
                                           related_name="import_logs")

  started_at                               DateTimeField

  duration_seconds                         FloatField(null=True,
                                           blank=True)

  status                                   CharField(max_length=20,
                                           choices=Status.choices,
                                           db_index=True)

  imported_counts                          JSONField(default=dict)

  skipped_counts                           JSONField(default=dict)

  errors                                   TextField(blank=True,
                                           default="")

  warnings                                 JSONField(default=list)

  created_at                               DateTimeField(auto_now_add=True)
  -----------------------------------------------------------------------

## Status Choices

``` python
class Status(models.TextChoices):
    SUCCESS = "success", "Success"
    FAILED = "failed", "Failed"
    DRY_RUN = "dry_run", "Dry Run"
    PREVIEW = "preview", "Preview"
    ROLLBACK = "rollback", "Rollback"
```

## Ordering

``` python
ordering = ["-started_at"]
```

## `__str__()`

``` python
return f"{self.get_status_display()} import at {self.started_at:%Y-%m-%d %H:%M}"
```

# 14. Delete Policy

  Parent             Child              Action
  ------------------ ------------------ -----------
  Subject            Chapter            CASCADE
  Subject            Lecture            PROTECT
  Routine            Lecture            CASCADE
  Routine            Exam               CASCADE
  Lecture            LectureTopic       CASCADE
  Lecture            RevisionSchedule   CASCADE
  Chapter            LectureTopic       PROTECT
  LectureTopic       Progress           CASCADE
  User               Progress           CASCADE
  User               RevisionSchedule   CASCADE
  RevisionSchedule   RevisionHistory    CASCADE
  User               DatasetVersion     SET_NULL
  DatasetVersion     ImportLog          SET_NULL
  User               ImportLog          SET_NULL

`DatasetVersion`/`ImportLog` deliberately use `SET_NULL`, not
`CASCADE`, on their `User` links (Milestone 10) - deleting a user
account should never delete the historical record that dataset import
happened, only lose the attribution of *who* ran it. Likewise deleting
a `DatasetVersion` (not currently possible from any UI in this
project, but not prevented at the schema level either) leaves its
`ImportLog` rows intact with `dataset_version=NULL`, rather than
silently erasing audit history.

# 16. Version 1 Constraints

Out of scope for Version 1:

-   ~~User authentication~~ ~~Multi-user support~~ - implemented in
    Milestone 7 (Django's built-in `django.contrib.auth`; no custom
    user model). This document's original "out of scope" listing is
    kept struck through here rather than silently deleted, per
    PROJECT_PROGRESS.md's "never delete history" convention.
-   Historical progress snapshots
-   Soft deletion
-   Audit logging (`RevisionHistory` and `ImportLog` are narrow,
    purpose-specific exceptions - not general-purpose audit logging
    for every model)
-   File attachments
-   Tags or categories
-   Custom managers
-   Signals (Milestone 9's revision-schedule auto-creation is
    triggered by an explicit service-layer call from
    `ProgressToggleView`, not a Django signal)
-   Business logic in models
-   Model methods beyond `__str__()`
-   Notifications or reminders (explicitly deferred past Milestone 9;
    scheduled for a later milestone)
-   Background/scheduled jobs (revision schedules are created
    synchronously and inline, not via a task queue or cron)
